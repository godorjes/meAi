# Polyglot 极简模型配置与网络异常处理修改说明

日期：2026-09-15  
状态：待实施的修改规格。本次只编写文档，不修改 App 代码、不部署模型目录服务。

## 1. 修改目标

普通用户只需要输入 API Key，其他信息尽量通过选择或自动填写完成：

**选择厂家 → 粘贴 API Key → 选择模型 → 测试连接／保存。**

模型选择不能依赖厂家接口实时连通。即使某个厂家接口不可达，也能查看已有模型目录、选择模型并保存配置；实际聊天是否可用，由对应服务的真实请求决定。

本次目标不包含修复全部网络环境问题，也不承诺任何网络下都能访问所有厂家。

## 2. 与既有要求的关系

- 延续“数据不可非主动丢失”：刷新失败、模型下线、目录解析失败、网络切换不能删除已有配置、密钥、模型选择、聊天或草稿。
- 调整此前“配置名称必须手动填写”的要求：普通流程自动生成有效名称；名称仍须在保存后有效，但不要求用户输入。高级设置允许改名。
- 保留此前下拉框整块可点击、测试按钮整块响应、按钮与右侧测试状态同步的要求。
- 测试失败不阻止保存格式有效的配置。
- 此文仅覆盖配置流程、目录和网络状态。会话标题、侧边栏宽度、换模型副本等其他需求按原任务执行。
- 数据层改动必须使用无损迁移，不能通过清库、卸载重装或 wipe-data 解决兼容问题。

## 3. 当前实现及需调整的问题

根据本轮读取的代码：

| 现有实现 | 需要修改的原因 |
| --- | --- |
| ProviderPresets 写入厂家、默认 API 地址和获取 Key 的帮助地址 | 可以保留；需要补充各厂家模型查询能力及协议适配 |
| OpenAiClient 统一请求 baseUrl + /models | 不能假设所有厂家或接入服务都提供同样的列表接口 |
| model_catalog.json 提供内置种子 | 作为首次安装和完全离线时的基础；模型 ID 和描述须经过核实 |
| modelOptions 合并公共目录与表单在线结果 | 缺少清晰来源与验证状态，参考条目容易被当作账号可用模型 |
| catalog_models 以 providerType + modelId 为主键 | 适合公共资料，不适合保存不同账号各自的查询结果 |
| upsertFromNetwork 按厂家刷新并 pruneProvider | 一个账号查不到某模型不代表厂家下线，不能据此删除公共目录 |
| 切换厂家只更新厂家与地址 | 旧模型列表、已选模型和晚到请求可能污染新厂家表单 |
| 获取列表默认选择 models.first() | 接口顺序不代表推荐顺序，第一个模型也不一定支持当前聊天协议 |
| 每 24 小时通过 WorkManager 尝试刷新 | 可以保留尽力更新，但不能成为页面正常使用的前提 |
| 配置名称为空时阻止保存 | 与极简配置目标冲突，需要自动命名 |

本轮为静态检查；未调用用户真实 Key，也未验证所有厂家在当前网络下的可达性。

## 4. 页面布局与交互

### 4.1 默认页面

| 顺序 | 控件 | 行为 |
| --- | --- | --- |
| 1 | 厂家下拉框，必选 | 选择后自动使用已核实的默认地址和协议 |
| 2 | API Key 输入框，必填 | 默认隐藏，支持粘贴与临时显示 |
| 3 | 模型下拉框，必选 | 先显示本地目录；支持点选，可选搜索仅用于缩小列表 |
| 4 | 测试连接按钮及右侧状态 | 只测试当前选定模型，状态同步 |
| 5 | 保存按钮 | 必填项和格式有效即可保存，测试失败也能保存 |
| 6 | 高级设置，默认折叠 | 配置别名、自定义地址、手动模型 ID 等 |

下拉框文字、箭头和空白区域均能打开选择器。模型较多时列表滚动；不强迫用户输入搜索词。

接口类型由 App 按厂家适配，不作为普通用户需要理解或填写的字段。

### 4.2 自动填写与必填校验

- 配置名称按厂家自动生成，例如“DeepSeek 配置”；重复时增加数字。自动命名要在保存时防止快速连点产生重复配置。
- 若用户在高级设置主动填写别名，保存修剪后的有效文字；别名为空则回退自动名称。
- 厂家须为支持的选项；Key 不得为空或纯空格；模型必须已选或在高级设置填写有效 ID。
- 预设地址由 App 提供；用户进入自定义模式后，地址仍需校验 HTTPS 和合法主机名。
- 不通过 Key 的外观推断一定有效，不将其发送给多个厂家探测归属。
- 校验失败显示字段级提示并定位首个问题，不发起测试请求，不丢弃已填内容。

### 4.3 自动获取模型的触发时机

- 选择厂家后立即展示本地模型目录，不等待网络。
- Key 粘贴完成或输入框失焦后，可自动尝试获取当前配置模型列表；保留手动刷新入口。
- 输入每个字符时不发请求。同一厂家、地址和凭证版本的重复触发合并为一次进行中的请求。
- 模型列表查询与聊天测试分开。自动查询列表不触发付费聊天测试；测试只由用户点击。
- 切换厂家时取消旧查询、清空当前表单旧模型选择及账号查询结果。不同厂家的旧 Key 不自动带过去调用；已保存的原配置不受影响。
- 更换 Key 或地址后，旧账号查询结果不再作为当前凭证的查询证据，但公共参考目录仍可选。

## 5. 模型目录方案：本地可读，联网增强

### 5.1 三类数据分开管理

| 数据 | 来源和范围 | 用途 |
| --- | --- | --- |
| 公共模型目录 | 内置 JSON + 我们维护的远程公开目录，按厂家组织 | 让用户随时能够选择已知模型 |
| 当前配置查询结果 | 用户选定服务的官方列表接口，按配置隔离 | 补充、核对该配置当前查询到的模型 |
| 当前配置测试结果 | 选中模型的实际聊天测试 | 记录该配置、模型、参数在某时刻测试的结果 |

“目录存在”“服务返回”“上次测试成功”是不同证据，不能相互替代。

页面始终从本地保存的数据生成列表，后台刷新成功后再更新本地数据和界面。这是展示时机上的本地优先，不代表把过时目录当作最新事实。

### 5.2 首次安装、缓存和官方结果

1. 首次安装立即读取随包内置的已核实目录。
2. 有通过校验的远程公共目录缓存时，使用较新版本作为公共资料。
3. 当前配置官方查询成功时，优先展示返回且适配当前聊天协议的模型；参考目录中的其他模型放到“参考模型／更多模型”，不要无差别混入主要列表。
4. 官方查询失败、接口不支持或没有缓存时，公共参考目录仍能选择，明确标记待验证。
5. 已保存的模型即使不再出现在新列表中，也保留原值并标注“本次列表未返回”；不能自动替换、删除或静默切换模型。
6. 当前 Key 查询不到某个模型，不能据此判定该模型在整个厂家范围下线。

内置目录只能覆盖已核实模型，不能承诺永远包含所有新模型。确实没有目标模型时提供刷新目录和高级设置中的手动 ID 入口。

### 5.3 公共目录如何维护

推荐使用静态 JSON 托管或 CDN，无需为了目录引入账号系统或聊天后端。

- 维护端依据厂家官方文档、公开资料和经过验证的接口更新目录；网页搜索只辅助维护，结果需核实后发布。
- App 读取固定、可信的 HTTPS 目录地址。目录请求不携带用户 API Key、聊天正文或配置明细。
- 元数据包含 schemaVersion、catalogVersion、publishedAt、厂家 ID、准确模型 ID、显示名称、来源地址和核实时间。
- 能力资料可以包含支持的协议、文本输入／输出等；不明确的字段保留为未知，不编造“最新”“免费”“最快”等结论。
- 远程数据仅为模型资料，不允许通过目录修改 Key 的发送地址或下发可执行内容。
- 对格式、版本、大小、重复 ID、支持的厂家和字段进行校验；校验通过才原子替换目录。
- 下载、解析或校验失败时保留最后有效版本；完全无缓存时继续使用内置目录。
- 可采用 24 小时过期检查：页面先读缓存，再刷新；WorkManager 尽力更新。24 小时不是精确执行承诺。
- 远程目录托管地址、发布权限和维护负责人须在后续部署阶段确定；本轮不创建或部署服务。未部署时内置目录和厂家查询仍须可用。

### 5.4 每个厂家的查询适配

| 厂家 | 当前方案 |
| --- | --- |
| OpenAI | 官方文档提供模型列表接口，按该厂家适配查询 |
| DeepSeek | 官方文档提供模型列表接口，按该厂家适配查询 |
| Kimi | 官方文档提供模型列表接口，注意地址与凭证所属平台匹配 |
| 智谱 | 当前已查到官方模型概览，但尚未核实本 App 接入方式下可靠的通用模型列表接口；先使用已核实目录，完成接口验证后再启用查询 |
| 自定义兼容服务 | 高级模式使用用户指定地址，支持查询则读取，不支持则用该配置缓存或手动 ID |

接口支持和网络可达性是两件事：官方有接口不等于当前手机能访问。不能在运行时猜测多个域名并携带用户 Key 轮流试探。

## 6. 模型筛选与状态

### 6.1 筛选规则

- 默认列表面向当前 App 的文字聊天协议。
- 根据可靠能力资料排除明确不兼容的向量、图片生成、语音专用模型；支持文本聊天的多模态模型不因“多模态”而被排除。
- 不仅凭模型 ID 的字符串特征判定能力。
- 新发现但能力未知的模型放入“其他模型”，标注需验证；不静默丢弃全部新模型。
- 不直接使用接口返回第一项作为默认模型。
- 有当前有效选择时保持选择；新增配置默认提示选择。若以后提供推荐项，其排序依据必须来自已核实资料，不自动发起请求。

### 6.2 展示状态

| 状态 | 文案 | 含义 |
| --- | --- | --- |
| 公共参考条目 | 参考模型，待验证 | 有资料，但未证明当前配置可调用 |
| 当前配置官方查询结果 | 服务返回 | 当前配置查询到该模型，不等于聊天一定成功 |
| 当前参数测试成功 | 上次测试成功 | 显示测试时间，不表示实时在线 |
| 当前查询缓存过期 | 列表暂未更新 | 可继续选择与保存，后台更新不阻塞 |
| 已选模型未出现在新列表 | 本次列表未返回 | 保留配置，允许用户主动测试或重选 |

避免用一个“可用”布尔值概括权限、网络、协议、额度和历史测试状态。

## 7. 网络异常处理

### 7.1 处理矩阵

| 情况 | 页面行为 | 是否可保存 | 是否能保证聊天 |
| --- | --- | --- | --- |
| 手机明确无网络 | 展示本地目录，保留表单与历史 | 可以，字段有效即可 | 不能 |
| 公共目录服务器不可达 | 使用最后有效目录／内置目录 | 可以 | 与厂家聊天接口另行判断 |
| 厂家列表请求超时 | 提示“暂时无法更新模型列表，已展示本地目录” | 可以 | 可能能，允许单独测试聊天 |
| 厂家不提供列表接口 | 使用公共参考目录或配置缓存 | 可以 | 需测试聊天 |
| 厂家列表可访问、聊天不可达 | 保留选项，测试区提示连接失败 | 可以 | 不能 |
| 某厂家不可达，其他厂家可达 | 仅更新失败厂家的状态 | 可以 | 由各自请求决定 |
| 服务明确返回凭证错误 | 提示检查 Key，不显示虚假成功 | 可以保留配置 | 不能据此继续宣称可用 |
| 模型不存在／无权限 | 保留旧选择并提示重选或检查权限 | 可以 | 当前模型未通过 |
| 原因不能确认 | “请求失败，请重试” | 可以 | 不作保证 |

厂家的认证成功与否应根据明确的服务响应判断；不能把所有 403、404 或连接异常一律解释为 Key 错误。

### 7.2 网络检测与请求策略

- 不把 Wi-Fi 已连接、系统显示有网等同于所有厂家可达。
- 查询状态按厂家／接入地址／当前配置分别维护，不能一家失败导致全 App 禁用。
- 目录请求采用有限时限，建议连接超时 5 秒、总时限 10 秒；这些是初始工程参数，应在弱网验收后调整。
- 聊天测试使用独立有限总时限，例如 30 秒；不能无限等待。
- 目录 GET 请求可有限重试或等待下次刷新；主动刷新操作可重新发起。
- 聊天和聊天测试不在失败后自动重复提交，防止重复生成或额外用量。
- 监听网络变化时可以重新安排目录更新，但不要自动重发聊天或把历史测试成功改成实时在线。
- 每个请求携带内部请求 ID 与配置修订版本；厂家、地址或 Key 变化时取消旧请求，并丢弃所有晚到旧结果。

### 7.3 聊天服务完全不可达

提供“重试连接”“选择其他已配置服务”“高级设置”操作。用户更换网络或主动选择其他服务后再尝试。

本地目录只能解决模型选择，不会让不可达的聊天服务自动恢复。若以后支持第三方接入，应明确区分模型厂家和实际接入服务，使用对应服务凭证。不得自动转发官方 Key 给第三方，不得静默切换厂家／模型。

本轮不建设请求代理、网关或后台保活服务。

## 8. 测试连接与保存

- 测试按钮整个区域响应，按钮与右侧文字从同一份 StateFlow 派生。
- 状态依次为未测试、测试中、成功／失败；开始后双方立即显示“测试中…”，结束后按钮恢复可操作。
- 只测试用户选定的模型，不遍历目录批量调用。
- 请求参数根据厂家和模型协议适配，不能假设所有模型都接受同一套最小参数。
- 校验实际聊天响应；HTTP 2xx 或模型列表返回成功不能替代聊天验证。
- 修改 Key、地址、厂家或模型后，当前测试结果失效；旧请求结果不能覆盖新参数状态。
- 测试未保存表单不回写旧配置的测试结论。
- 保存时只携带与最终参数一致的测试结果；失败或未测试也可保存。
- 配置、密钥及必要模型选择可靠提交后才提示保存成功，写入失败保留表单和旧数据。

## 9. 数据结构建议

| 数据 | 推荐主键／关联 | 内容 |
| --- | --- | --- |
| 公共目录条目 | providerType + modelId | 名称、能力、来源、核实时间、目录版本 |
| 配置模型快照 | configId + endpointRevision + credentialRevision + modelId | 当前配置查询到的模型、查询时间 |
| 模型验证记录 | configId + 参数版本 + modelId | 结果、测试时间、错误分类 |
| 表单请求状态 | 临时表单 ID + requestId + 参数版本 | 进行中、错误、是否允许应用返回结果 |
| 目录更新状态 | 目录来源 ID | 最后成功版本、更新时间、缓存状态 |

credentialRevision 是本机凭证版本号，不保存明文 Key，也不将 Key 拼接到缓存路径或日志。新建未保存配置使用临时表单作用域；保存后再关联正式 configId。

公共目录更新、配置查询结果与测试结果分别写入，不再用某个账号结果 prune 公共厂家目录。所有 schema 变化提供无损迁移，旧数据保留。

## 10. 代码修改范围与建议顺序

| 顺序 | 文件／模块 | 修改内容 |
| --- | --- | --- |
| 1 | data/local/Entities.kt、Daos.kt、AppDatabase.kt 及迁移 | 区分公共目录与配置快照，保存来源、版本和查询时间 |
| 2 | data/repo/CatalogRepository.kt | 本地优先读取、内置／远程目录更新、原子替换、失败保留 |
| 3 | data/net/OpenAiClient.kt、ChatStreamClient 及厂家适配层 | 查询能力区分、有限超时、明确异常、解析模型资料 |
| 4 | data/repo/ConfigRepository.kt | 查询结果按配置隔离，保留选择，禁止账号查询覆盖公共目录 |
| 5 | feature/config/ConfigViewModel.kt | 自动命名、请求版本校验、切换厂家重置、自动查询触发、单一测试状态 |
| 6 | feature/config/ConfigEditScreen.kt | 默认三项配置、高级设置折叠、状态和字段提示、整框点击 |
| 7 | work/CatalogRefreshWorker.kt | 公共目录与配置查询分别更新，各厂家失败互不影响，失败不清空 |
| 8 | app/src/main/assets/model_catalog.json | 校验准确 ID、能力资料和来源，移除未经证实的宣传描述 |
| 9 | 聊天页模型选择器 | 复用正确的配置模型数据，不能把公共参考目录自动当成已配置可用模型 |
| 10 | 自动化测试与模拟器验收 | 按下一节覆盖网络、旧结果、保存及数据保留 |

以上 Kotlin 路径均位于 app/src/main/java/app/polyglot/dev/。本次不要求升级整套依赖或拆成多个应用模块。

- [ ] 模拟 DeepSeek 可达、Kimi 超时、OpenAI 不可达时，三者状态独立。
- [ ] 仅 /models 失败而聊天可用时，能够从参考目录选模型并完成测试。

### 14.2 与规格的偏差

1. **快照表主键**用 `configId + modelId`，版本号作为普通列而不是主键的一部分。
   规格建议 `configId + endpointRevision + credentialRevision + modelId`，但那样每换一次 Key 就多留一整组行；
   现在改为"同一模型只保留最近一次查询的版本"，旧版本行在读取时按版本过滤掉，效果相同而表不会无限增长。
2. **远程公共目录地址留空**（`CatalogRepository.PUBLIC_CATALOG_URL`）。规格本就写明本轮不部署目录服务，
   因此未配置时整条下载流程跳过，内置目录与厂家查询照常可用；解析／校验／原子替换的代码路径已实现并有测试覆盖。
3. **配置列表页仍显示配置级测试汇总**（沿用 `providers.testState/testedAt`，在记录测试结果时一并更新）。
   按模型记录测试结果的 `model_verifications` 已落地，但列表页没有改成逐模型展示。

### 14.3 界面简化（按使用反馈调整）

规格 §4.1 与 §6.2 原本要求"公共参考目录单独成组"，实测后按使用反馈简化如下：

| 调整 | 做法 | 保留的约束 |
| --- | --- | --- |
| 厂家列表去掉 OpenAI | `ProviderPresets` 增加 `selectable` 标记，OpenAI 不再出现在新增配置的选择列表里 | **保留 OpenAI 的预设定义**（地址、帮助链接），历史配置仍能正确显示名称与地址，不会被误判成"自定义" |
| 参考模型不再单独成组 | 取消独立的「参考模型」下拉，改为**一个模型列表**：当前凭证查到的 → 配置保存的 → 公共目录条目 | 规格 §6.2"不同证据不能相互替代"改由**行内标注**承担：`服务返回`／`本次列表未返回`／`待验证` |
| 去掉手动刷新按钮 | 勾选厂家即自动获取（此时已有 Key 才会发请求）；Key 失焦后自动再试一次；打开模型选择器时若上次没拿到结果自动重试。同一参数重复触发仍合并为一次请求 | 规格 §4.3 的自动触发时机与"输入每个字符不发请求"不变；列表失败仍不阻塞选择与保存 |

真机验收：厂家下拉为 GLM（智谱）／DeepSeek／Kimi／自定义，无 OpenAI；
模型下拉直接列出所选厂家的全部条目并逐行标注来源；页面上无"刷新列表"入口；
选中模型后表单正常；改动前后数据库五个表内容哈希逐字一致。49 项仪器化测试通过。
