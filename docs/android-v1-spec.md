# 安卓首版开发说明

版本：v0.1 · 日期：2026-09-14 · 项目暂称：Polyglot

本文整理已确认的产品交互，并给出可执行的首版建议。它是开发准备文档，尚未代表安卓功能已经实现。整理本文前，工作区只有 `ui-preview.html`，可作为视觉参考。

## 1. 产品目标与决策状态

让用户在安卓手机上配置自己的模型 API Key，完成稳定的文字对话，并能保存历史、停止回复、失败重试和换模型续聊。

| 项目 | 状态与约定 |
| --- | --- |
| 运行平台 | 用户已确认：安卓 App |
| 首次使用 | 用户已确认：优先引导配置 API Key |
| 停止生成 | 用户已确认：按钮位于输入框右侧 |
| 失败恢复 | 用户已确认：尽量简单；本方案采用原地重试、保留输入 |
| 删除撤销 | 用户已同意提供撤销；本方案默认提供 5 秒撤销窗口 |
| 开发路线 | 建议：Kotlin + Jetpack Compose 原生安卓 |
| 数据与账号 | 建议：手机直连模型服务、本地保存，首版无需账号和自建后端 |
| 首版交付 | 暂按可安装 APK 内测安排；是否公开上架尚未确定 |

## 2. 首版范围

| 首版交付 | 后续再评估 |
| --- | --- |
| 服务配置新增、编辑、删除、测试连接 | 登录、云同步、多设备同步 |
| 获取模型列表，支持手动填写模型 ID | 更多非兼容协议、局域网模型服务 |
| 文字消息、流式回复、停止、重试 | 图片、文件、语音输入与朗读 |
| Markdown、代码块展示与复制 | 知识库、独立联网搜索 |
| 会话列表、标题、搜索、删除与撤销 | 多模型并行回答、工具调用 |
| 换模型创建独立会话 | 聊天分支编辑、历史回复多版本切换 |
| 聊天、配置、草稿的本地保存 | 导入导出、自动备份、主题切换 |

首版不展示没有实现的联网、知识库、附件、指令、账号入口。效果图中的模型名称只用于示意，实际列表读取用户配置，不硬编码模型能力或可用性。

## 3. 页面与导航

| 页面 | 内容与主要操作 |
| --- | --- |
| 首次使用页 | “连接模型，开始对话”；“配置 API Key”；获取 Key 的帮助入口 |
| 模型服务列表 | 配置名称、上次测试结果、模型数量；添加和编辑入口 |
| 配置详情 | 名称、服务商、接口类型、API 地址、API Key、模型选择；测试和保存 |
| 聊天页 | 会话标题、当前模型、消息、输入框、发送／停止、回复重试 |
| 历史会话抽屉 | 新建、搜索、按时间分组的会话、重命名／删除、模型设置入口 |
| 换模型弹窗 | 当前模型标识、目标模型、标题、复制范围说明、创建操作及失败提示 |

无配置时打开首次使用页。有可用配置时恢复上次会话；没有会话则显示空聊天页。会话有记录但对应配置已删除时，仍可阅读历史，发送位置显示“请选择模型”。

## 4. 服务配置

1. 服务商预设负责填写默认 API 地址；用户可修改地址。首版只接入已验证的 OpenAI 兼容文本聊天协议，不承诺任意服务都兼容。
2. API Key 默认隐藏，允许临时显示。保存后再次进入编辑页仍隐藏；日志、错误提示和分享内容不得包含 Key。
3. 模型列表优先从服务读取。服务不提供列表时，允许手动填写模型 ID，列表读取失败不直接认定 Key 无效。
4. “测试连接”使用所选模型发送最小文本测试请求；按钮旁说明“测试可能产生少量用量”。测试期间防止重复点击。
5. 保存要求必填字段有效，但测试失败不禁止保存，方便弱网时保留配置。首次保存后返回聊天页，发送失败按第 6 节处理。
6. 配置状态显示“未测试”“上次测试成功”“上次测试失败”，不把历史测试结果当作实时在线状态。修改地址、Key 或测试模型后清除旧测试结果。
7. 删除配置同时删除对应密钥材料；聊天保留模型名称快照。影响正在生成的配置暂不允许删除或修改，提示先停止回复。

## 5. 发送、生成和停止

- 首版同一时间只运行一个生成请求。生成时仍可编辑下一条草稿，但不能再次发送；右侧按钮显示停止方块。
- 点击发送先持久保存用户消息，再开始请求；失败后消息仍在会话中。发送前未能保存时保留输入并提示，避免出现看似发送成功却丢失记录。
- 首条有效提问的前 20 个字符作为默认会话标题，去除换行；用户可以重命名，不额外调用模型生成标题。
- 回复分段出现；代码块可横向滚动并复制，普通 Markdown 链接只在用户点击后打开。
- 点击停止后取消客户端请求，保留已收到内容并标记“已停止”，按钮恢复发送。客户端停止不承诺服务端立刻停止处理或计费。
- 已停止或中断的部分回复保留用于阅读，但不作为完整答案自动加入后续请求上下文。
- 用户查看较早消息时不强制滚动；提供“回到底部”入口。用户位于底部时跟随新内容滚动。

## 6. 回复失败与重试

| 场景 | 提示和操作 |
| --- | --- |
| 明确无网络 | “网络不可用，请连接后重试”＋重试 |
| 连接超时、中断、服务暂时不可用 | 对应简短原因＋重试 |
| 服务明确返回凭证无效 | “API Key 无效，请检查配置”＋去设置 |
| 服务明确返回额度不足 | “服务额度不足，请检查账户”＋去设置 |
| 服务明确返回限流 | “请求过于频繁，请稍后重试”＋重试 |
| 模型不存在或不支持 | “模型不可用，请重新选择”＋选择模型 |
| 上下文超出限制 | “对话过长，请新建会话或选择容量更大的模型” |
| 原因无法确认 | “请求失败，请重试”，不猜测是 Key、额度或网络问题 |

重试只针对最后一个尚未成功完成的回复。它复用对应用户消息，不再次插入同一条提问，也不发送输入框里的新草稿。历史中间消息的重新生成不纳入首版。

已有部分回复时，不将新结果接到旧结果末尾。旧内容保留到新请求开始返回正文，再用新正文替换该回复的显示内容；重试尚未返回正文就失败时，旧内容仍可阅读。首版不提供版本选择器。

重试时原始上下文保持一致，不把旧的失败回复发给模型。不自动重试可能产生重复生成的请求。连续点击只启动一次请求。

## 7. 换模型续聊

1. 点击顶部模型名称打开弹窗。展示已配置的具体模型，当前模型用文字标识，不使用锁图标；不同模型分别列出。
2. 新会话复制当前文字记录及完成状态，保留来源会话 ID 和来源标题。原会话不变，后续修改互不影响；输入框草稿保留在原会话，不自动发送或复制。
3. 生成中先提示停止回复，再创建副本。失败或已停止的会话允许换模型，避免原服务故障时无法恢复。部分回复在副本中仍可阅读，但不作为完整答案加入请求，弹窗说明“未完成回复仅保留供阅读”。空会话直接选择模型，无需创建副本。
4. 标题默认空白且必填（**2026-09-15 变更**：原为“默认‘原标题 · 目标模型’”，因自动拼接的标题会被用户直接当结果提交，
   且空标题能创建出无名会话，改为默认留空、显示必填标识、未填写时提示“请输入新会话标题”并阻止创建）。
   点击“创建新会话并继续”仅创建并打开副本，不自动调用目标模型重复回答最后一题；用户发送下一条消息后开始使用目标模型。末轮未完成时，在副本中提供“重试”，使用新模型回答该条原始提问，上下文按新模型容量重新检查。
5. 创建是本地保存操作。成功后才关闭弹窗并跳转；失败显示“创建失败，请重试”，保留模型选择和标题。重复点击、重试不产生多个副本。
6. 来源会话仍存在时，可从新会话返回来源。来源被删除后保留来源标题，去掉不可用的跳转入口。
7. 不静默截断记录。容量已知且估算超限时提前提示；无法可靠判断时，在服务返回超限后给出明确提示。创建成功不代表目标服务一定可接受全部上下文。

## 8. 删除与撤销

- 删除后会话立即从列表隐藏，显示“会话已删除 · 撤销”，默认持续 5 秒；开启辅助功能时按系统建议延长可操作时间。
- 撤销恢复原会话、消息和列表位置。删除当前会话时先回到空聊天页，撤销后恢复该会话。
- 撤销窗口内只做带截止时间的软删除，结束后才永久删除。应用重启时清理已过期删除；未过期则恢复剩余撤销机会。
- 首版同一时间只保留一条待撤销删除；窗口结束或撤销前暂不允许删除第二条，避免覆盖第一次撤销入口。
- 删除正在生成的会话时同时取消请求；撤销只恢复数据，不自动重新请求。

## 9. 安卓适配与数据恢复

| 情况 | 首版行为 |
| --- | --- |
| 软键盘弹出 | 输入框随键盘上移，发送／停止可见；允许多行输入 |
| 系统返回 | 按当前最上层状态处理键盘、弹窗、抽屉及页面返回，不一次退出多层 |
| 旋转、窗口尺寸改变 | 保留会话、草稿与生成状态，不重复发请求 |
| 切到其他 App、锁屏 | 本方案主动结束进行中的客户端生成，保留部分内容并标记中断；不配置后台持续生成服务 |
| 系统回收进程 | 重开后恢复已落盘数据，把遗留“生成中”改为“已中断”，不自动重发 |
| 未发送草稿 | 按会话保存；空聊天页也保存独立草稿 |
| 网络恢复 | 不自动重复发送，交由用户重试 |

流式回复增量定期保存，并在停止、失败、正常结束时立即保存；异常强制结束可能丢失最后一小段未落盘文字，不承诺逐字符恢复。

设计采用安卓状态栏、手势区和系统返回行为，不照搬效果图的设备外框。控件触控区域至少 48dp，重要图标提供朗读标签；验证小屏、横屏和系统大字体。相关依据见 [Android 触控与无障碍说明](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)及[状态保存说明](https://developer.android.com/topic/libraries/architecture/saving-states)。

## 10. 建议的技术与数据方案

原生方案使用 Kotlin、Jetpack Compose、ViewModel 和协程。界面只呈现状态并发出用户操作；数据层统一处理模型请求和本地保存。首版采用一个应用模块，按聊天、配置和数据职责分包，避免过早拆分。该方向参考 [Android 官方架构建议](https://developer.android.com/topic/architecture/recommendations)。

| 数据 | 保存内容与原则 |
| --- | --- |
| 模型服务 | 配置 ID、名称、地址、协议、模型列表、测试时间与结果；Key 另行加密保存 |
| 会话 | ID、标题、服务及模型引用、模型名称快照、来源 ID／标题、时间、删除截止时间 |
| 消息 | ID、会话 ID、角色、顺序、正文、状态、请求关联标识、错误分类 |
| 草稿和界面状态 | 每个会话草稿、空会话草稿、当前会话、必要的滚动位置 |

聊天和服务元数据建议使用本地数据库，轻量偏好单独保存。请求任务由会话状态管理，不能随页面重新绘制重复创建。会话副本和删除恢复采用原子操作，避免只复制一半或出现重复记录。

API Key 通过本机加密密钥加密保存；加密密钥使用 [Android Keystore](https://developer.android.com/privacy-and-security/keystore) 保护。首版默认使用 HTTPS，不支持任意明文地址或关闭证书校验。Key 仅发送到用户配置的服务地址，不写入源码、日志、分析事件或安装包。

首版不启用聊天和凭证的自动云备份／设备迁移，卸载后不承诺恢复，设置页明确说明。数据库更新需提供迁移，升级应用不能通过清空数据解决兼容问题。普通日志不记录聊天正文；首版不集成广告或第三方行为分析。

## 11. 开发顺序与验收

| 阶段 | 可验证的交付 |
| --- | --- |
| 1. 建立最小闭环 | 安卓安装包能启动；配置 Key；发送文字；读取流式回复；重开后记录仍在 |
| 2. 完成聊天状态 | 停止、错误分类、重试、草稿、旋转及后台中断恢复 |
| 3. 完成会话管理 | 历史列表、搜索、重命名、删除撤销、换模型副本 |
| 4. 真机验收 | 键盘、大字体、小屏、弱网、长对话、升级数据保留及密钥存储检查 |

首版验收至少覆盖：

- [ ] 首次安装可完成“配置 → 测试 → 保存 → 首次对话”。
- [ ] 至少两个真实服务配置通过文字流式对话验证；具体模型以测试时实际可用 ID 为准。
- [ ] Key 无效、模型不可用、断网、超时、限流分别给出可操作提示。
- [ ] 连续点击发送、重试或创建副本不会重复生成消息或会话。
- [ ] 停止保留已收到内容，生成结束后按钮恢复发送。
- [ ] 重试不会发送新草稿，不重复插入原问题，也不拼接两次回答。
- [ ] 旋转不会重复请求；切后台和锁屏后保存中断内容；重开不一直显示生成中。
- [ ] 换模型副本与原会话相互独立，失败可恢复；创建本身不自动调用模型。
- [ ] 删除后可撤销；删除期限和恢复状态在重启后正确处理。
- [ ] 删除服务配置不删除历史；没有配置时仍可读历史。
- [ ] 输入框不被键盘遮挡，长代码可滚动，大字体下主要操作仍可见。
- [ ] 至少一段长对话正常展示；服务拒绝超长上下文时有明确提示。
- [ ] 日志和安装包不含测试 Key，测试后凭证可在配置中移除。
- [ ] 更新安装包后聊天与配置仍在；卸载造成的数据变化符合产品说明。
