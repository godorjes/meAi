# Polyglot 聊天页交互与配置校验修改方案（5 项）

> 立项日期：2026-09-15。本文件只整理任务，**本轮未修改任何源码与既有文档**。
> 执行时逐项验证；源码已改、构建通过、界面文案变化都**不等于**验收通过。

**Goal:** 修正聊天页顶部标题与换模型入口的布局与行为，让「切换模型」真正作用到后续请求；
新会话标题改为必填；侧边栏收窄到约屏幕三分之一；添加模型服务页统一必填样式与逐字段校验。

**前置依赖：** 上一轮《数据可靠性与配置交互修改方案》的 A—F 已实施。本方案不得破坏其中的约束：
升级不重建数据库、写入先落盘再展示、发送走单事务、草稿版本化顺序写入、切换模型不改动原会话数据。

**验收重点（本方案贯穿性判据）：**
> 切换后的**实际请求**必须使用新模型；界面名称变化不能单独作为切换成功的依据。

这条要求决定了第 2 项的验收方式：必须取到真正发出去的请求参数（服务配置 + 模型 ID），
而不是看顶部标题或弹层文案是否变了。

## 1. 会话标题居中

**现状**
- `feature/chat/ChatScreen.kt:163` 的 `TopAppBar` 用 `title = { Column(horizontalAlignment = CenterHorizontally) { ... } }`（`:164`）。
- Material3 的 `TopAppBar` 标题只是导航图标之后的剩余槽位，槽位本身左对齐，所以标题是**在剩余空间内居中**，
  而不是相对屏幕居中；`navigationIcon`（菜单按钮，`:197`）越宽，标题越偏右。

**改动要点**
- 换成 `CenterAlignedTopAppBar`，它按整条 bar 的宽度计算居中，不受两侧图标宽度影响。
- 标题 `Text` 保持 `maxLines = 1` + `TextOverflow.Ellipsis`（已在 `:170-171`），并加
  `modifier = Modifier.fillMaxWidth()` 让省略号在真正可用宽度处生效。
- 第二行的模型名不再放在标题列内（见第 2 项），标题只剩一行，居中判定变简单。

**涉及文件：** `feature/chat/ChatScreen.kt`

**验收**
- 会话名在**有左菜单、有右上角按钮**两种情况下都相对屏幕水平居中（用 `uiautomator dump` 取标题节点 bounds，
  左右边距差 ≤ 2px）。
- 超长标题（例如 60 个字符）单行省略，不换行、不挤压两侧图标。

**风险：** `CenterAlignedTopAppBar` 在小屏 + 大字体下标题可用宽度变小；需在 33% 侧边栏那一版一并看小屏表现。

## 2. 调整切换模型入口，并修复切换不生效

**现状**
- 入口是顶栏标题下方的一枚圆角 chip（`ChatScreen.kt:174-193`，`onClick` 在 `:177`），点开
  `ModalBottomSheet`（`SwitchModelSheet.kt`，宿主在 `ChatScreen.kt:273`）。位置在标题列内，与第 1 项冲突。
- 顶栏**没有** `actions` 槽位。

**已定位的根因（必须按此修，否则只是换个入口）**

`ChatViewModel.kt:189` 在 `send()` 里用 `val current = session.value` 读取当前会话。
`session` 是 `_currentSessionId.flatMapLatest { chatRepo.observeSession(it) }.stateIn(...)`（`:53-55`），
它的值是**异步**更新的：`switchModel` 创建副本后调用 `openSessionInternal(copy.id)`（`:378`）只改了
`_currentSessionId`，`session.value` 要等 Room 查询回来才会变成新副本。
在这个窗口内点发送，`current` 仍是**旧会话**，于是 `configId` / `modelId` 取到旧值，
请求发给旧模型——而顶栏（稍后从同一个 Flow 更新）显示的是新模型名。
这与验收重点描述的"界面名称变了、实际请求没变"完全对应。

同样的隐患在 `ChatViewModel.kt:356`：`switchModel` 也用 `session.value` 判断"空会话可直接改 vs 有内容要建副本"，
副本路径的判断同样可能读到旧会话。

**改动要点**
- 入口：顶栏加 `actions = { IconButton(...) }`，图标可用 `Icons.Default.SwapHoriz` 或现有 `KeyboardArrowDown`，
  `contentDescription = "换模型续聊"`；移除标题列内的 chip。
- 展开为"换模型续聊"页面（见「待决事项」的形态选择）。
- **不再用 `session.value` 参与发送判定**。把 `send()` 与 `switchModel()` 里对当前会话的读取改成
  从数据库按 id 直读：`chatRepo.sessionById(_currentSessionId.value)`，与 `retry()`（`:245`）的既有写法一致。
  这样"用哪个配置和模型发请求"只依赖已落盘的事实，不依赖 Flow 的调度时序。
- 切换成功后：打开新副本、顶栏模型名从副本的 `modelNameSnapshot` 更新、后续 `send()` / `retry()`
  都从新副本读 `configId` / `modelId`；原会话与其消息一行不改。
- 失败与重复点击：`SwitchModelSheet.kt:243` 已有 `enabled = !creating`，但 `creating` 是弹层内局部状态，
  页面化之后要保证按钮在请求返回前始终不可点，且失败时**保留已选目标与已填标题**（`:134-137` 现有逻辑保留）。

**涉及文件：** `feature/chat/ChatScreen.kt`、`feature/chat/ChatViewModel.kt`、`feature/chat/SwitchModelSheet.kt`（或新的换模型页面）

**验收（本项的核心，必须取真实请求）**
- 新增仪器化测试：`GenerationCoordinator` 记录每次 `GenerationRequest` 的 `configId` / `modelId`。
  走完整"选中目标 → 创建 → 发送"，断言发起请求用的是**目标** `configId` 与 `modelId`。
  此测试不得依赖任何界面文案。
- 真机核对：切换到另一家服务配置后发一条消息，从 `messages` 与 `sessions` 表确认新会话的
  `configId` / `modelId` 是目标值，且原会话的消息条数与正文哈希不变。
- 创建失败注入（例如目标配置被删）后：弹层不关闭、已选目标与标题仍在、提示明确；连点 3 次只产生 1 个副本
  （比对 `sessions` 表新增行数）。

**风险：** 这是本轮唯一涉及请求参数的改动，回归面最大；改完必须重跑上一轮的 18 项仪器化测试。

## 3. 新会话标题默认空白且必填

**现状**
- `SwitchModelSheet.kt:77-84`：标题初始值 = `listOfNotNull(current?.title?.ifBlank { "新会话" }, initialTarget?.modelId).joinToString(" · ")`，
  即自动填成"原标题 · 模型名"。
- 选择目标模型时还会再次覆盖标题（`:157-161`）。
- 提交时**没有**任何标题校验，空标题也能创建。

**改动要点**
- 初始值改为空字符串；选择目标模型时**不再回填**标题。
- 标签加必填标识（与第 5 项统一的样式，例如标签后加红色 `*`）。
- 提交校验：`title.isBlank()`（同时覆盖空串与纯空格）→ 不提交，在输入框下显示
  `"请输入新会话标题"`，并把焦点定位到该输入框。
- 校验通过才调用创建；创建请求进行中禁用提交按钮。

**涉及文件：** `feature/chat/SwitchModelSheet.kt`（或新的换模型页面）

**验收**
- 标题框初始为空（`uiautomator dump` 该节点 `text` 为空）。
- 输入纯空格后点创建：不产生新会话，出现"请输入新会话标题"。
- 填有效标题后能创建，新会话标题等于输入值（不是拼接值）。

**与既有规格的冲突（需要你裁决，不擅自改规格）**
`docs/android-v1-spec.md` 第 7 节第 4 条写的是"标题默认『原标题 · 目标模型』，允许修改"。
本项要求默认空白且必填，与该条**直接冲突**。建议把该条更新为"标题默认空白，必填"，并在规格里留一句变更记录；
在得到确认前，规格与实现会不一致。

## 4. 侧边栏宽度调整为约屏幕三分之一

**现状**
- `ChatScreen.kt:130-133`：`ModalNavigationDrawer { ModalDrawerSheet { ... } }`，`ModalDrawerSheet` **没有宽度修饰符**，
  用的是 Material3 默认宽度 `DrawerDefaults.MaximumDrawerWidth = 360dp`。本机 411dp 宽，抽屉占了约 87%。
- 手势未显式关闭，`ModalNavigationDrawer` 默认支持右划打开、点遮罩与返回键关闭，这部分已符合要求，只需回归确认。
- 遮罩（scrim）是 `ModalNavigationDrawer` 的既有行为，剩余区域本来就保留聊天页并压暗。

**改动要点**
- `ModalDrawerSheet(modifier = Modifier.width(...))`，宽度取 `LocalConfiguration.current.screenWidthDp * 0.33f`，
  并设下限（建议 ≥ 240dp），避免小屏或大字体下窄到不可用。
- **窄宽度下的行内布局必须一起改**：`SessionDrawer.kt:171-186` 的一行是
  `图标(16dp) + 间距(10dp) + 标题(weight 1f, 省略) + 模型名徽标`。模型徽标当前**没有宽度约束**，
  在约 136dp 的抽屉里会把标题挤到几乎为零。建议把模型名移到标题下方一行（两行式），
  或在该宽度下隐藏徽标只留标题；标题继续 `maxLines = 1` + `Ellipsis`。
- 列表已是 `verticalScroll`（`ChatScreen.kt:134-138`），确认无法把抽屉撑宽。

**涉及文件：** `feature/chat/ChatScreen.kt`、`feature/chat/SessionDrawer.kt`

**验收**
- `uiautomator dump` 取抽屉根节点宽度，与屏幕宽度比在 0.30—0.36 之间。
- 右划屏幕右缘能打开同一个抽屉；点遮罩、按返回键都能关闭，返回键不会直接退出应用。
- 40 字符长会话名在同一行内省略，不换行、不撑宽抽屉；会话数超过一屏时可滚动。

**风险：** 33% 是很窄的抽屉，属于"你要求的最优解 vs 可用性"的取舍点。若实机觉得太窄，
可改为 `min(0.33 * 屏宽, 260dp)`；这一点执行时先按 33% 做，若长标题仍不可读再回来讨论。

## 5. 添加模型服务页统一必填样式与校验

**现状**
- 校验只有 `ConfigViewModel.kt:298` 的 `private fun validate(f: ConfigForm)`，返回**一条**字符串，
  经 `_message` → Snackbar 弹出；字段本身没有 `isError`，也没有 `supportingText`。
- `ConfigEditScreen.kt` 的字段（`:132` 配置名称、`:143` 服务商、`:187` API 地址、`:199` API Key、`:230` 模型）
  都没有必填标识，保存按钮（`:363`）直接调 `vm.save()`。
- 已有 HTTPS 前缀校验（`validate` 内），失败不写入数据库。

**改动要点**
- 统一必填样式：这些字段的 `FieldLabel`（`:376`）加必填标识；预选的有效值（服务商默认 OpenAI、
  接口类型"OpenAI 兼容格式"）视为已填写，不额外报错。
- 校验规则集中到 ViewModel 的一份结构化结果里（字段 → 错误文案），由 ViewModel 持有，
  页面只渲染，避免"同一规则散落在界面与 ViewModel 两处"：
  - 配置名称：`isBlank()` → "请填写配置名称"
  - 服务商：必须为已知预设
  - API 地址：`isBlank()` → "请填写 API 地址"；不满足 `https://` → "首版仅支持 HTTPS 地址"；
    能通过 URL 解析（host 非空）否则 → "API 地址格式不正确"
  - API Key：`isBlank()` → "请填写 API Key"
  - 模型：`isBlank()` → "请选择或填写模型 ID"（下拉选择与手动填写都算有效）
- 字段下用 `supportingText` + `isError` 显示**对应**提示；保存时若有错，阻止保存并
  `FocusRequester` 定位到**第一个**出错字段（顺序：名称 → 服务商 → 地址 → Key → 模型）。
- 测试连接：只校验请求必需字段（地址、Key、模型），名称缺失**不阻止**测试；
  缺字段时给提示且**不进入"测试中"**（上一轮已实现，需回归确认）。
- 测试失败不阻止保存（现有行为，需回归确认）。

**涉及文件：** `feature/config/ConfigEditScreen.kt`、`feature/config/ConfigViewModel.kt`

**验收**
- 逐个字段留空/填纯空格，分别在**该字段下方**出现对应提示，且保存被阻止、焦点落到第一个错误字段。
- `http://` 地址被拒并提示 HTTPS 要求；`https://` 但非合法 URL 被拒。
- 必填齐全（服务商与接口类型用预选值）时可正常保存；保存后配置与密钥同事务写入（沿用上一轮实现）。
- 测试连接在缺 Key 时提示且不出现"测试中…"；测试失败后仍能保存。

### 8.2 任务 2 的根因与修法

`ChatViewModel.send()` 原来用 `val current = session.value` 取当前会话。`session` 是
`_currentSessionId.flatMapLatest { observeSession(it) }.stateIn(...)`，取值**异步**更新：
`openSessionInternal(copy.id)` 只改了 `_currentSessionId`，要等 Room 查询回来 `session.value` 才变成副本。
这个窗口内点发送就会用旧会话的 `configId`/`modelId` 发请求——顶栏（稍后从同一个 Flow 更新）显示新模型名，
于是表现为「名字变了、请求没变」。`switchModel()` 里也有同一处写法。

改法：两处都改成按 `_currentSessionId.value` 从数据库直读（`chatRepo.sessionById(...)`），
与 `retry()` 原有写法一致——「用哪个配置和模型发请求」只依赖已落盘的事实，不依赖 Flow 的调度时序。

为让这条验收可测，把流式客户端抽成接口 `ChatStreamClient`（`OpenAiClient` 实现它），
`GenerationCoordinator` / `ConfigRepository` 依赖接口。新增的 6 项测试用可控假客户端断言
**真正发出去的 `baseUrl` / `modelId` / `apiKey`**，而不是界面文案。

### 8.3 执行时发现并修复的问题

**空草稿行（我上一轮引入的）**：`openSession` 会对离开的会话做一次草稿提交，
文本为空时也写行，于是**只要点开过某个会话就会留下一行空草稿**。
用户设备上已实际出现 3 行（`new` + 两个会话），无内容损失。
修法：`appendDraft` 在「文本为空且本来没有草稿行」时直接跳过（返回 0），已存在的草稿被清空时仍写，
保证「清空」这个动作同样有序可判定。新增测试覆盖，并清掉了设备上那 3 行。

### 8.4 与方案不同的决定

1. **换模型页面**用应用内整页（`SwitchModelPage` + `BackHandler`），没有做导航路由。
   理由：导航到新路由会拿到另一个 `NavBackStackEntry` 作用域，`ChatViewModel` 会换实例，
   `_pending`、草稿、生成状态都会丢——正是「切换不生效」那一类问题的温床。
   整页形态下返回键语义、页面观感与独立路由一致，且状态不跨作用域。
2. **任务 3 的标题对空会话不显示**：会话没有内容时不会创建副本，也就没有新会话需要命名，
   隐藏标题框、按钮显示「使用该模型」。原来的弹层会显示标题框但**静默丢弃**用户输入的标题，这里顺带修掉了。
3. **侧边栏宽度先按严格 33% 做过一版，随后调整为 300dp**（见 8.6）：33% 在手机上约 136dp，
   为了塞下内容只能压缩内边距、把模型名挤到第二行，观感很差。改为按平台惯例取值。
4. **已同步更新规格**：`docs/android-v1-spec.md` 第 7 节第 4 条由「标题默认『原标题 · 目标模型』」
   改为「默认空白且必填」，并在该条内留下变更说明，不是静默改规格。

### 8.6 侧边栏宽度的最终取值（替代第 4 项原先的 33%）

33% 那一版实测宽度 356px（32.96%），代价是内边距从 20dp 压到 12dp、会话标题字号降到 12.5sp、
模型名只能用 9.5sp 挤在第二行——按你的反馈「太丑」调整为：

```
宽度 = min(屏宽 - 72dp, 300dp)，下限 260dp
```

理由：手机上的会话抽屉读起来大致在屏宽 70%—80%（Material 的模态抽屉上限是 360dp）；
300dp 能放下搜索框与够长的会话标题，同时留出 72dp 让遮罩可见。
内边距、字号、图标尺寸一并恢复到原来的舒适取值（表头 20dp、标题 13.5sp、模型名 11sp），
会话行保留两行式——模型名再长也不会挤压标题。

实测：遮罩起点 x=788 → **788/1080 = 73.0%（= 300dp）**，遮罩区留出 292px。
几何自检：表头文字起点 145px 与「20dp 内边距 + 26dp 标志 + 9dp 间距」吻合；
会话标题起点 120px 与「10+10dp 内边距 + 16dp 图标 + 10dp 间距」吻合；
所有节点最右止于 351px，远在抽屉右边界内。
遮罩有效性用像素采样验证：抽屉关闭时该区域 `avgRGB=(255,255,255)`，
打开时 `avgRGB=(173,173,173)`——正是 32% 黑色遮罩叠加白色的结果（255×0.68≈173）。

**我本人看不到图片**（当前模型不支持图像输入），所以这个宽度是**依据平台惯例与几何自检**定的，
不是"我看过觉得好看"。截图已存到 `docs/screenshots/`（`01-drawer.png`、`03-switch-model-page.png`、
`04-switch-with-title.png`、`05-config-field-errors.png`），请你看一眼；若嫌宽或嫌窄，改的是
`ChatScreen.kt` 里 `drawerWidth` 一行。

## 9. 验收阶段你报的 4 个问题（同日修复）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 换模型页总是高亮列表第一项 | `initialTarget` 取"第一个非当前项"，当前模型排第一时就跳到第二项，看起来永远落在第一个 | 默认选中**当前模型**；没有当前会话时不预选，必须显式选择 |

### 9.1 实机验收证据

- **问题 1**：在 deepseek 会话（当前模型是列表第一项 `deepseek-flash`，第二项是 `deepseek-v4-pro`）直接创建副本，
  副本拿到的是 `deepseek-flash`。旧逻辑会取"第一个非当前项"即 `deepseek-v4-pro`，两者可区分，故为决定性证据。
- **问题 2**：新增测试「反复更换模型不会让模型列表不断变长」与「选中的模型不在服务列表里时仍然可见」。
  你已有的那条 deepseek 配置里两个模型是历史累积的结果，**需要你点一次「获取模型列表」**用服务真实返回的列表覆盖它
  （该配置有 Key，实测可获取）；此后换模型不会再往列表里加东西。
- **问题 3**：点搜索框后 `mInputShown=true`；点遮罩后抽屉收起且 `mInputShown=false`；
  返回键路径同样为 `true → false → false`，第二次返回只关抽屉不退出应用。
